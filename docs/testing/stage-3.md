# 第三階段測試清單

分支：`claude/stage-3`。這一階段把內部改成「積木插槽」架構，並加上快捷鍵編輯、匯出匯入、相容橋接的基本部分。

## 這一版做了什麼

- **五種插槽**（規格 3.8），內建功能都走同一套：
  - 顯示方式：`BarDisplayModeDef`。原版、摺疊、捲動、摺疊＋捲動現在是 XML 定義（`Defs/MainButtonBarSystem/BarDisplayModes.xml`）。
  - 外觀：`BarAppearanceDef`。內建「原版」。
  - 相容橋接：`CompatBridgeDef`。內建 TooManyButtons、Custom Bottom Bar。
  - 按鈕預設值：其他模組在自己的 `MainButtonDef` 上加 `MainButtonBarSystem.MainButtonBarDefaults` 擴充。
  - 查詢：`MainButtonBarAPI`（列上有哪些按鈕、抽屜裡有哪些、列的位置）。
  - 給附屬模組作者的英文說明：`docs/API.md`。
- **快捷鍵編輯**（規格 3.6）：進階模式選一顆按鈕，「快捷鍵：X [設定] [清除]」。
  - 原版有快捷鍵設定的按鈕：用遊戲的設定視窗，存在 `KeyPrefs.xml`，「選項 → 鍵盤設定」看到的一樣。
  - 原版沒有的按鈕：本模組自己存，所有存檔共用。
  - 撞鍵時顯示紅字警告。
  - 被隱藏、收進抽屜的按鈕，快捷鍵照樣有效。
- **匯出匯入**（規格 3.9）：設定畫面右下「匯出…」「匯入…」。
  - 匯出：複製成文字、存成檔案、複製成模組 XML（排序積木）。
  - 匯入：從剪貼簿、從匯出的檔案、從排序積木模組。
  - 匯入只改視窗裡的工作副本，要按「儲存」才會保留。
- **相容橋接**（規格 3.7）：偵測到 TooManyButtons 或 Custom Bottom Bar 時，設定畫面上方出現提示。進階的「整條列」有優先級選項，**改了要重開遊戲才生效**。
  - 預設是「對方優先」：裝了本模組不會打斷對方。
  - 「本模組優先」：移除對方在主按鈕列方法上的 Harmony 補丁；TooManyButtons 改過的 `buttonVisible`、`order` 還原成基準線。
  - 對方設定值的參考顯示、「匯入它的設定」：下一階段才做。

## 步驟

1. 開遊戲、讀檔，確認沒有紅字。設定畫面的顯示方式清單應該還是那四種，名稱是中文。
2. **快捷鍵**：
   - 選一顆原版有快捷鍵的按鈕（例如「建築」），進階 → [設定] → 按一個鍵。到「選項 → 鍵盤設定」看是不是同一個鍵。
   - 選一顆原版沒有快捷鍵的模組按鈕，[設定] 一個鍵，關掉設定畫面後按那個鍵，應該打開那個分頁。
   - 故意設一個撞鍵的，應該看到紅字警告。
   - 把那顆按鈕隱藏或收進抽屜，快捷鍵應該照樣能用。
   - 在任何文字輸入框打字時，自訂快捷鍵不應該觸發。
3. **匯出匯入**：
   - 調好一個排法 →「匯出…」→「複製成文字」，貼到記事本看看是可讀的 XML。
   - 「全部重設」→「匯入…」→「從剪貼簿」：排法應該回來（按儲存才會保存）。
   - 「存成檔案」：訊息會告訴你存在哪裡；「匯入…」清單裡應該看得到那個檔案。
   - 「複製成模組 XML」：內容是可以直接放進模組 `Defs` 的 XML。
4. **相容**（只在有裝 TooManyButtons 或 Custom Bottom Bar 時）：上方提示、進階的優先級；改成「本模組優先」並重開遊戲後，log 會列出被移除的補丁，主按鈕列由本模組畫，對方不再畫。

## 要帶回雲端的資料

- 有沒有紅字或黃字。
- 前兩個階段還沒帶回的診斷資料（`Stage 1 diagnostics`、`Patches on main button methods`、`buttons.tsv`）。
- 如果有裝 TooManyButtons 或 Custom Bottom Bar：`Patches on main button methods` 的內容特別重要，下一階段的相容功能要靠它確認對方的 Harmony id 和組件名稱。
