# 第二階段測試清單

分支：`claude/stage-2`。這一階段開始有正式功能：設定資料、每個存檔分開存、預設範本、設定畫面（簡單＋部分進階）、「更多」抽屜。第一階段的測試用設定已經拿掉，換成正式的設定畫面。

## 這一版做了什麼

- **設定存在存檔裡**（規格 3.4）：`MainButtonBarGameComponent`。新遊戲、第一次載入的舊存檔都從預設範本開始；沒有範本就是「沒改過」。
- **預設範本**：`Config/MainButtonBarSystem_Template.xml`。在主選單打開設定改的就是範本；遊戲中可以「存成預設範本」「套用預設範本」。
- **沒改過就不接管**（反目標）：設定是「原版＋沒有任何改動」時，仍由遊戲自己畫主按鈕列。模組設定裡有一個測試用的「總是由本模組繪製」可以強制接管，用來比對。
- **設定畫面**（規格 3.1、3.2）：
  - 入口：選項 → 模組設定 → Main Button Bar System →「主按鈕列設定」；或遊戲中「更多」抽屜下方的按鈕。
  - 左邊清單：第一列是「整條列（預設值）」，下面每顆按鈕一列：拖曳把手、顯示、圖示（沒有就空白）、名稱、來源模組、（進階）快捷鍵、抽屜。可拖曳排序或用「上移」「下移」。原本 `buttonVisible=false` 的按鈕在底部「原本不顯示」群組。
  - 右上：選「整條列」時是顯示方式四選一和寬度設定；選按鈕時是資訊（按鈕來源、圖示來源、defName）、顯示、抽屜、自訂名稱；進階再加寬度、固定位置、強制顯示、快捷鍵（唯讀）。
  - 右下：存成預設範本、套用預設範本、全部重設、取消、儲存。
  - **即時預覽**：畫面開著時，改動直接反映在下方主按鈕列；取消或按 ✕ 會還原。
- **菜单鎖定**：預設鎖在最右邊，只能改名。進階的「整條列」可以解鎖。
- **「更多」抽屜**：摺疊、摺疊＋捲動模式下，勾了「抽屜」的按鈕收進「更多」；抽屜是格狀彈窗，下方有設定按鈕；抽屜沒東西時「更多」不出現。
- **改名**：直接改 `MainButtonDef.label` 並清掉標籤快取；取消改名就還原成基準線的名稱。

## 步驟

1. 主選單 → 選項 → 模組設定 → 打開設定：標題應該寫「預設範本」。隨便調一個排序後按儲存，檢查 `Config/MainButtonBarSystem_Template.xml` 有產生。再打開一次，「全部重設」→ 儲存，恢復原狀。
2. 載入存檔：主按鈕列應該和沒裝本模組時一樣（沒改過＝由遊戲繪製）。
3. 打開設定（標題應該寫「目前存檔」）：
   - 拖曳排序、上移下移：下方的列跟著即時變動。
   - 取消顯示幾顆：馬上消失。用快捷鍵開被隱藏的按鈕（例如把「建築」隱藏後按 B）應該照樣能開。
   - 改名：輸入新名稱，列上的文字即時變；按「還原」變回去。
   - 按「取消」：所有改動應該還原。
4. 再改一次後按「儲存」→ 存檔 → 回主選單 → 讀檔：設定應該保留。
5. 顯示方式：
   - **摺疊**：勾幾顆「抽屜」，列上出現「更多（N）」，點開是格狀抽屜；點抽屜裡的按鈕會開對應視窗、抽屜關閉；抽屜下方的設定按鈕能打開設定。抽屜開著時再點「更多」應該關掉（不會關了又開）。
   - **捲動**：和第一階段相同（滾輪不縮放地圖、箭頭、菜单固定）。
   - **摺疊＋捲動**：兩者同時。
6. 進階：寬度（單顆）、固定位置（左端／右端）、強制顯示、間距、填滿畫面、解鎖菜单。
7. 「存成預設範本」後開一個新遊戲：新遊戲的排法應該是範本的排法。

## 請本機確認的實作假設

- 改名時把 `MainButtonDef` 的 `cachedLabelCapWidth`、`cachedShortenedLabelCapWidth` 設成 `-1` 表示「要重算」，`cachedShortenedLabelCap` 設成 `null`、`Def.cachedLabelCap` 設成空值。雲端的參考組件沒有方法內容，請從遊戲的 `Assembly-CSharp.dll` 確認原版的哨兵值是不是 `-1`（看 `MainButtonDef` 的欄位初始值和 `LabelCapWidth` getter）。如果不是，改名後按鈕文字可能被截斷或寬度不對。
