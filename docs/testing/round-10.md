## 這輪做了什麼

來自 2026-11-05 的整體設計評測（四個面向的靜態審查）。

| 項目 | 內容 |
|---|---|
| 圖示快取 | 本模組畫按鈕時，原本會先記下 def 的圖示欄位（還沒載入時是 null）、再載入圖示，畫完又把 null 寫回去，所以每次繪製都要重新經 `ContentFinder` 掃過所有模組找圖。改成先載入再記住。只要套了主題、對齊或圖示模式，讀檔後沒開過設定視窗就會發生，所以以前的測試容易漏掉 |
| 例外防護 | Harmony 補丁改成逐類別套用：遊戲更新後某個目標方法壞了，只關掉那個功能（黃字），不會讓後面的補丁全部套不上。每個補丁本體都包 try/catch：主按鈕列出錯時這次遊戲交給遊戲畫；全域的 `ButtonTextSubtle`／`DrawAtlas` 補丁出錯時關掉自己，不影響遊戲其他地方的按鈕；相機和快捷鍵補丁只記一次錯誤。讀設定、查相容橋接這幾步移進保護範圍 |
| 單顆按鈕出錯 | 某顆按鈕在點擊之類的輸入時丟例外：算它自己壞了，只記一次紅字並寫出按鈕和來源模組。畫的時候丟例外：先照遊戲原本的方式再畫一次它，也丟例外就是它自己壞了（記一次、跳過）；畫得出來就是本模組對這顆的畫法（主題、圖示設定）出問題，之後這顆照遊戲的方式畫，其他按鈕照常。以前是整條列退回原版，抽屜裡則每幀刷紅字 |
| 私有欄位 | 用反射讀的遊戲私有欄位（icon、allButtonsInOrder、label 快取）改成找不到時只警告一次、關掉那個功能，不會讓整個類別初始化失敗 |
| 摺疊溢出 | 摺疊模式關閉「填滿畫面」時，放不下的按鈕以前會壓到「更多」和菜单底下或跑出畫面；改成等比例縮小到放得下 |
| 數字框 | 原版 `TextFieldNumeric` 會用自己的名字蓋掉控制項名稱，本模組永遠判斷成「沒在打字」，打到一半的文字每幀被重設。改成自己判斷焦點和解析：只有打字會改數值，打字途中可以清空、可以先打出超出範圍的中間值，數字落在範圍內時才套用；拖滑桿、按預設、換一顆按鈕時框裡改顯示新的值；點框外或按 Enter 結束編輯。每顆按鈕的寬度框各自獨立 |
| 順序跟著遊戲 | 玩家沒設定順序時，以前用啟動時記下的順序；只要本模組接手畫列（例如只換了主題），其他模組在執行期改的順序就失效。改成跟著遊戲當下的 `MainButtonsRoot.allButtonsInOrder`；玩家設了順序之後以玩家的為準。TooManyButtons 選「本模組優先」時，它已經改過的那一局清單不採用，改用原本的順序 |
| UI Rethemed 提示 | 新的「只提示」相容定義 `CompatNoticeDef`（全部寫在 XML：packageId、用反射讀的開關、「開關狀態 × 誰畫列 → 提示文字」），內建 [LFS] UI Rethemed - Main Bar。偵測到它啟用時讀 `UIRethemed.MainBar.MainBar.Settings.mainButtons`，依「它的 Main bar 開關」和「上一次是誰畫列」在設定視窗頂端顯示黃字；不做優先切換、不拿掉它的補丁。讀不到開關時當作不確定：不顯示、不報錯，只在開發模式記一行。開發模式第一次畫列時記一行偵測結果。工作坊說明也加了一句 |
| 每幀配置 | 存檔元件只在換遊戲時重找；有效順序在設定沒變時沿用；「更多（N）」的文字和寬度在數量、語言、字型沒變時沿用；版面的輸入物件重複使用；改名同步和「未自訂」判斷不再每次配置 |

## 步驟

### A. 圖示快取（效能，最重要）

1. 用作者的大型排序（約 2,200 個模組）。新遊戲或讀檔，外觀選一款內建主題（例如帝國），按儲存，存檔。
2. 回主選單、讀那個存檔，**不要打開設定視窗**。
3. 比較這個分支和 main 的每幀成本，擇一：
   - 有 Dubs Performance Analyzer（或其他 1.7 能用的分析工具）時：看 `MainButtonsRoot.MainButtonsOnGUI`／`DoButtons` 的每幀時間。
   - 沒有分析工具時：同一個存檔、同一個鏡頭，比較遊戲內 FPS（開發模式的 FPS 顯示，或外部工具）。
4. 預期：main 上這個情境明顯比「原版外觀」慢；這個分支和「原版外觀」差不多。

### B. 例外防護

1. 開發模式啟動，記錄本模組的紅字和黃字：應該 0 紅字；log 裡不應出現「Could not apply …」或「Field … was not found」（有的話代表 1.7 的某個欄位或方法改名了，請整段貼回來）。
2. 一般操作 10 分鐘（開各分頁、組商隊選路線讓按鈕停用、切換顯示方式、開抽屜）：沒有新的紅字。
3. （選做，需要編譯一個小測試模組）做一顆 `MainButtonDef`，它的 worker 覆寫 `DoButton` 直接 `throw new Exception("test")`：
   - 放在主列上：log 只出現一次紅字「Main button … (from …) threw while being drawn」，其他按鈕照常、可以點，列仍由本模組畫（主題、順序都在）。
   - 收進抽屜再打開抽屜：同樣只有一次紅字，抽屜其他格子照常。
   - 另做一顆只在**點擊時**丟例外的按鈕（例如 `Activate` 裡 throw）：點它只出現一次紅字「… threw while handling input」，列不會變成原版、主題還在。
4. （選做）用 XML 補丁把 `Tuning.xml` 的 `behaviour` 整段刪掉：
   - 啟動時有一行 Tuning 的設定錯誤（紅字，這是預期的，代表 XML 檢查有效）。
   - 進遊戲後最多再一行紅字「… failed; handing … back to the game for this session」，之後不再刷。
   - 主按鈕列由遊戲照原版畫，UI 其他地方（警報、視窗、相機）都正常，主選單也正常。

### C. 摺疊溢出

1. 顯示方式選「摺疊」，進階關掉「填滿畫面」，預設寬度拉到 200 以上，抽屜裡至少放一顆。
2. 預期：列上的按鈕縮小到剛好放得下，「更多」和菜单完整露出、都點得到；沒有按鈕跑出畫面。
3. 把寬度拉回 80，按鈕變回原本的寬度（放得下時不縮放）。

### D. 數字框

在進階的「預設寬度」（範圍 40～400）右邊的數字框：
1. 點進去、全選刪掉：框是空的，不會跳回原值。
2. 依序打 `3`、`35`、`350`：打到 `3`、`35` 時列上的寬度不變（超出範圍），打到 `350` 時立刻變成 350。
3. 打英文字母：打不進去。
4. 打到一半（例如 `3`）點到別處：框結束編輯、顯示目前的值（超出範圍的輸入被捨棄）。按 Enter 也一樣；點地圖或底部列（視窗外）也一樣，之後按數字鍵不會改到值。
   - 從「選項 → 模組設定 → Main Button Bar System」打開設定視窗時再按一次 Enter：只結束編輯，下面的模組設定視窗**不會**被關掉。
   - 單顆按鈕的寬度（預設 0）打 `150`、透明度（預設 100）打 `50`：每一位數都打得進去，最後是 150、50（不會在打到 `15`、`5` 時掉焦點）。
5. 打完一個值之後**不點別處**，直接拖旁邊的滑桿：數值跟著滑桿走，不會被拉回剛才打的值；按「預設值」：回到預設，不會在下一幀又變回打的值。
6. 每顆按鈕自己的寬度框（進階、選一顆按鈕）：在 A 打 `150`，再點清單裡的 B：B 的寬度**不變**，框顯示 B 自己的值；按取消離開後重開，A、B 都沒有被改到。
7. 位移（可以是負數）的數字框：可以先打 `-` 再打數字。
8. Esc 的行為記下來（Esc 可能直接關掉設定視窗，這是既有行為）。

### E. 順序跟著遊戲

1. 新存檔、什麼都不改，只在外觀選一款主題並儲存：列上的順序和原版一樣。
2. 進設定把某顆按鈕拖到別的位置、儲存：照你拖的順序。再按「全部重設」：回到遊戲的順序。
3. 如果手邊有會在遊戲中改主按鈕順序或新增主按鈕的模組（例如 DragReorder 選「本模組優先」時，它記住的順序）：只換主題、不改順序時，它的效果要保留。沒有的話這步跳過。
4. TooManyButtons 選「本模組優先」、重開遊戲：第一局和第二局（回主選單再讀檔）沒設順序時，列的順序都一樣，是原版順序。

### F. 回歸

1. 四種顯示方式各切一次，捲動、抽屜、固定左右、改名、隱藏、圖示四種模式都還正常。
2. 切換語言（不重開遊戲）後，列和設定視窗都正常、沒有紅字。
3. 主選單打開設定視窗改範本、儲存，開新遊戲：用的是範本。

### G. UI Rethemed - Main Bar（工作坊 3826865706）

背景：它和本模組的 `DoButtons` prefix 優先度相同，模組清單裡排前面的先跑。它的 Main bar 開著時會自己畫列；它把右下角控制項移進列、調整分頁視窗和世界檢視面板位置這些事，看的是 Main bar 開關，不是它有沒有真的畫列。

兩種模組順序 × 它的 Main bar 開／關，共四種，每種都要**重開遊戲**（順序和它的開關都在啟動時生效）。每種都：開發模式啟動、進遊戲、打開本模組設定視窗，看頂端黃字；然後關掉視窗看畫面。

| # | 模組順序 | 它的 Main bar | 本模組設定 | 預期黃字 | 預期畫面 |
|---|---|---|---|---|---|
| G1 | UI Rethemed 在前 | 開 | 先不改 | 「UI Rethemed - Main Bar 正在畫底部列，這裡的設定不會生效。……」 | 它的列 |
| G2 | UI Rethemed 在前 | 開 | 改一項（例如選一款主題），按儲存 | 同 G1 | 仍是它的列，本模組的改動看不到 |
| G3 | UI Rethemed 在前 | 關 | 改一項 | 沒有黃字 | 本模組的列；右下角控制項、分頁視窗位置正常 |
| G4 | 本模組在前 | 開 | 先不改 | 同 G1（見下方說明） | 它的列 |
| G5 | 本模組在前 | 開 | 在視窗裡改一項（例如選一款主題） | **當下**換成「UI Rethemed - Main Bar 的 Main bar 也開著……畫面可能錯位。……」 | 本模組的列；記下右下角控制項、分頁視窗、世界檢視面板有沒有錯位（預期可能錯位） |
| G6 | 本模組在前 | 關 | 改一項 | 沒有黃字 | 本模組的列；位置正常 |

另外：
1. 每種情況的 log 裡有一行「UI Rethemed - Main Bar: active; UIRethemed.MainBar.MainBar.Settings.mainButtons = True／False; bar drawn by …」。這行只記**讀檔後第一次畫列**的狀態，所以看的是存檔裡原本的設定，不是後來在視窗裡改的：
   - `mainButtons` 的值要和它的 Main bar 開關一致。
   - UI Rethemed 在前、Main bar 開（G1、G2）：「an earlier mod (this mod's prefix was skipped)」。
   - 本模組在前（G4～G6），或 Main bar 關（G3）：存檔還沒改過本模組設定時是「the game or a later mod (this mod left it: its settings are untouched)」；改過的存檔是「this mod」。
2. 主選單打開設定視窗（編輯範本）：不顯示 UI Rethemed 的黃字（主選單沒有底部列，判斷不了誰畫）。
3. 黃字很長時會換行，不會被切掉、不會壓到下面的分頁。換成英文、日文各看一次。
4. 只裝本模組、不裝 UI Rethemed：沒有黃字；log 是「UI Rethemed - Main Bar: not active.」。
5. G4 的說明：本模組在前、但設定還沒改時，本模組讓出繪製，所以是它畫列，提示照「它在畫列」那句；那句的「或把本模組排在它前面」在這個情況不適用。看實際感受，如果覺得會誤導，回報時寫下來，雲端再加一種說法。
