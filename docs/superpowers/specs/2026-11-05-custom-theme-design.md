# 外觀分頁：預設主題與自訂主題 設計文件

寫於 2026-11-05。來源：整體設計評測後作者的回覆（主設計文件 3.10）。【作者】是作者親口決定的，不要改；【判斷】是實作者的決定，作者可以推翻；【保留】是還要作者決定的。

---

## 1. 為什麼要做

作者的設計陳述 2：每顆按鈕都是獨立的元素，有自己的寬高、文字、圖示、按鈕背景、按鈕背景插圖，可以統一管理（所有按鈕一個樣），也可以個別微調。

現況（2026-11-05 評測）：按鈕的外觀只存在主題層。玩家只能整套換主題，不能只改某一顆，也不能只改某一項；主題 XML 只有背景插圖能指定到某顆按鈕。主題規格 3.8 又寫了「不加新的玩家滑桿」，所以玩家端完全沒有個別調整外觀的地方。

## 2. 目標、非目標、反目標

**目標**
- 玩家在遊戲裡就能調每顆按鈕的文字、圖示、按鈕背景、背景插圖，也能一次調所有按鈕。
- 可以從一款預設主題開始改，改好存成自己的主題、分享給別人。

**非目標（這次不做）**
- 寬度、高度：留在按鈕分頁【作者】。
- 整條列的背景、抽屜背景、「更多」和捲動箭頭、裝飾插圖：沿用起點主題，這次不開放調整。
- 「一鍵做成主題模組」（像排序那樣直接寫進 Mods 資料夾）：之後再說【保留】。

**反目標（不能發生）**
- 沒碰自訂主題的玩家，外觀和現在不同。
- 主題模式多出玩家滑桿（主題規格 3.8 只在主題模式成立）。
- 其他模組加在 `DoButton` 上的效果被洗掉：自訂主題和主題一樣，只在畫按鈕的期間替換貼圖、顏色、圖示，按鈕仍由遊戲的 `DoButton` 畫。

## 3. 作者已定的行為

### 3.1 兩種模式【作者】

- 外觀分頁上方切換「**預設主題**」或「**自訂主題**」，樣式和按鈕分頁左上的「簡單／進階」切換鈕一樣。
- 「預設」是**預先設計好的**意思，不是「預設值」。翻譯時要用「預先設計好的主題」那個詞（英文 Preset themes），不要和「預設值」按鈕用同一個詞。

### 3.2 預設主題【作者】

- 列出模組已知的每種主題：內建、附屬模組提供的，以及玩家存下來的自訂主題。
- 選了就套用（熱切換）。

### 3.3 自訂主題【作者】

- 左側是和按鈕分頁左側差不多的按鈕清單。**最上面一列是「所有按鈕」**，所有按鈕的樣式一起調。
- 選一列之後，右側是可調整的外觀：
  - 右上：顯示這顆按鈕（或所有按鈕）目前的樣子。
  - 目前樣子的下方：可調整的項目。
  - 右下：做成和按鈕分頁一樣（見 3.5）。
- 可以先在預設主題選好一款，再切到自訂主題，以那款的外觀當起點微調。

### 3.4 可調整的項目【作者】

| 項目 | 內容 |
|---|---|
| 文字 | 對齊（靠左／置中／靠右）、字級、一般／滑鼠移上／開啟中三種狀態的文字顏色 |
| 圖示 | 大小、**位置** |
| 按鈕背景 | 一般／滑鼠移上／按下或開啟中／停用四種狀態的框 |
| 背景插圖 | 圖、填法（填滿裁切／完整放入／拉伸）、錨點、透明度、內縮 |

### 3.5 右下的按鈕：和按鈕分頁一樣【作者】

- 所有改動先在畫面上預覽：「儲存」才寫進存檔，「取消」還原。
- 匯出、匯入管整套外觀，和按鈕分頁的匯出整份排法一樣。
- 匯出：把整套外觀（「所有按鈕」那一層加上每顆的微調）存成一份**自訂主題**，之後會出現在預設主題的清單裡，也能分享。

### 3.6 圖的來源【作者】

按鈕背景和背景插圖的圖，兩種來源都可以：
- 直接挑已安裝主題（內建、附屬模組）裡的貼圖。
- 匯入自己的 PNG。放在存檔資料夾，和匯入的圖示一樣，Steam 更新不會清掉。

## 4. 實作者的判斷（作者可檢查）

1. **預設主題也有同一組底部按鈕**：現在的外觀分頁沒有儲存、取消，要切回按鈕分頁才能存。兩種模式都放和按鈕分頁一樣的底部按鈕，位置也一樣（右下）。
2. **熱切換也要按儲存**：點預設主題立刻在畫面上看到，和其他改動一樣，按「儲存」才寫進存檔，誤點還能反悔（依 3.5）。
3. **右上預覽並排四種狀態**：一般、滑鼠移上、開啟中、停用，不用真的把滑鼠移上去才看得到。預覽由本模組自己畫，不經過 `DoButton`，所以其他模組加在 `DoButton` 上的效果不會出現在預覽裡，只會出現在真正的列上。
4. **改過之後換預設主題要先確認**：在自訂主題改過，再到預設主題點另一款時，跳確認「自訂的外觀會被換掉」，確定才換。
5. **每一項都是三層，逐項往上找**：這顆按鈕的值 → 「所有按鈕」的值 → 起點主題的值 → 原版。每一項都有自己的「預設值」按鈕，按了就回到「跟上一層」，不是整顆重設。資料用哨兵表示「沒改過」，和主設計 3.10 的逐欄位哨兵一致。
6. **改了哪些看得出來**：清單裡改過的按鈕有標記，「所有按鈕」那一列顯示「N 顆有自己的設定」，並有「全部改回跟隨所有按鈕」（比照圖示模式的做法）。
7. **單顆的樣式重複使用**：選一顆按鈕時有「複製樣式」「貼上樣式」，把一顆調好的樣式貼到別顆，不另外做檔案格式。
8. **圖示的「位置」**【保留，見 8.1】：建議是「錨點＋位移」。
   - 只顯示圖示：錨點有九個位置（左上到右下，預設置中），再加 X／Y 位移（像素）。
   - 圖示＋文字：圖示放在文字的左邊或右邊（預設左邊），再加 X／Y 位移。
9. **圖示模式「預設」的按鈕**：圖示模式是「預設」時，圖示由遊戲畫，位置和大小固定。這顆按鈕的圖示大小或位置一旦改過，就改由本模組自己畫圖示（和「只顯示圖示」同一套畫法）。代價和現在的「只顯示圖示」一樣：Vanilla Textures Expanded 這類改 `DoButton` 圖示位置的模組，對這顆按鈕就沒有作用。
10. **文字顏色的選法**：用遊戲內建的選色視窗；1.7 沒有的話，改用 RGB 滑桿加十六進位色碼框。
11. **字級**：用遊戲的三種字型（小、中、大），不做任意大小，因為遊戲只有這三種。
12. **按鈕背景的圖**：照遊戲按鈕的九宮格畫法（四角是貼圖寬的 1/4，最多 18px），所以建議 64×64，最大 72×72。匯入時超過這個大小只提示，不擋。
13. **起點主題**：從預設主題切到自訂主題時，記下當時選的那款當起點；沒改過的項目都跟它。之後在預設主題換別款，起點也跟著換（改過的項目照 4.4 先確認）。
14. **整條列的其他部分**：整條列的背景、抽屜背景、「更多」、捲動箭頭、裝飾插圖都照起點主題，外觀分頁原本的「插圖與背景」設定照常生效。
15. **存放**：自訂主題的資料存在 `BarConfig` 裡，跟著存檔走；在主選單編輯時存進預設範本，和其他設定一樣。存檔格式會升版，舊存檔讀進來時沒有自訂主題、外觀不變。
16. **檔案位置**：
    - 匯入的 PNG 放 `<存檔資料夾>/MainButtonBarSystem/Images/`（和 `Icons/` 分開，因為用途和尺寸不同）。
    - 存下來的自訂主題放 `<存檔資料夾>/MainButtonBarSystem/Themes/<名稱>/`：一份 XML，加上它用到的 PNG。名稱、作者、說明和排序匯出一樣可以填。
    - 匯入別人的自訂主題時，PNG 複製進 `Images/`，檔名重複就自動改名。
17. **在預設主題裡選一份自訂主題**：把它的內容複製進目前的設定，所以存檔不依賴那份檔案。之後檔案被刪掉，存檔照樣能用；只有用到的 PNG 不見時，才改用起點主題的值，警告只記一次。
18. **分享整份排法時**：排序匯出（`docs/API.md` 第 2 節）會帶著自訂主題的資料；用到的 PNG 照現在匯入圖示的方式處理，對方缺圖時，匯入報告會列出來。
19. **效能**：每顆按鈕最後生效的外觀算一次就存起來，設定改了才重算，每幀不配置記憶體。沒用自訂主題時完全不走這條路。
20. **數值不寫死**：新的範圍和預設值（圖示大小範圍、位移範圍、透明度、內縮等）都放 `Tuning.xml`。

## 5. 資料（草案）

```
BarConfig
  appearance        = 預設主題的 defName（現有）
  appearanceMode    = Preset | Custom（新）
  customTheme       = CustomThemeData（新，Custom 時使用）

CustomThemeData
  baseTheme         = 起點主題的 defName
  all               = ButtonLook（「所有按鈕」那一層）
  buttons           = List<ButtonLook>（每顆的微調，依 defName）

ButtonLook（每個欄位都有「沒改過」的哨兵）
  文字：labelAlign、labelFont、labelColor／labelMouseoverColor／labelActiveColor
  圖示：iconSize、iconAnchor、iconOffsetX、iconOffsetY
  按鈕背景：atlas／atlasMouseover／atlasActive／atlasDisabled（貼圖參照）
  背景插圖：image（貼圖參照）、fit、anchor、verticalAnchor、opacity、inset

貼圖參照
  主題貼圖：該主題模組裡的路徑，加上它來自哪個主題
  匯入的 PNG：Images/ 裡的檔名
```

## 6. 技術

- 畫法沿用現在的主題機制：`ButtonPainter` 在 `DoButton` 期間替換 atlas、文字顏色、圖示，`ThemeAtlasSwap` 先畫背景插圖再畫框。自訂主題只是把「這顆按鈕的值」換成三層合併後的結果。
- 選圖的視窗比照現在的圖示選擇器（`UI/Dialog_IconPicker.cs`）：一頁列出已安裝主題的貼圖，一頁列出匯入的 PNG，加上「匯入」和「開啟資料夾」。
- 新字串照慣例做 29 種語言。

## 7. 完成的定義

- 沒用自訂主題的存檔，外觀和這輪之前完全一樣（逐像素比對內建主題的預覽）。
- 每一項都能分別在「所有按鈕」和單顆上調，每一項都有預設值按鈕。
- 匯出的自訂主題換一台遊戲（或刪掉 Images/ 重開）能載入，缺圖時有提示、沒有紅字。
- 開發模式 0 紅字；`dotnet build` 0 警告、測試通過；新的合併規則（三層逐項往上找）有單元測試。
- 實機測試清單照慣例寫在 `docs/testing/`。

## 8. 保留給作者決定的【保留】

1. **圖示的「位置」指什麼**：4.8 的「錨點＋位移」可以嗎？還是只要位移就好？
2. **做的順序**：建議先做主設計 3.10 的「逐欄位哨兵」和「平分時尊重單顆寬度」（資料模型、存檔升版），再做這份。這份也可以拆兩輪：
   - 第一輪：文字、圖示、按鈕背景（只用主題貼圖）。
   - 第二輪：背景插圖、匯入 PNG、匯出與載入自訂主題。
3. **「一鍵做成主題模組」**：要不要像排序那樣，直接在 Mods 資料夾產生一個主題模組（含 About.xml、Def、貼圖）？
